# STEP 5｜真實版面檢查與修正紀錄

## 第一次設計完成後的瀏覽器測試

- 使用 Chromium 模擬桌機 1280×800 及手機 390×844，檢查 12 頁和互動功能。
- 桌機 12 頁沒有水平或垂直捲動。
- **手機第一次視覺檢查發現文字重疊**：原本 `work-grid` 在窄螢幕設定成 `flex:0`，造成內容容器被壓到近乎零高度；圖表和文案仍然渲染，但互相覆蓋。

## 局部 Loop：只修 HTML 響應式樣式

1. **錯誤定位**：HTML 渲染／版面關卡 E→G，而非 Wiki 引用關卡。這次不需要重讀 PDF，也不改動任何統計公式或證據卡。
2. **修改**：手機時將 `slide-content` 和 `work-grid` 設為內容自動高度，改用垂直排列並允許長頁向下捲動。
3. **再次測試**：重新生成相同 12 頁 HTML，完成 1280×800、390×844 雙尺寸的逐頁測試。
4. **結果**：沒有水平溢出；手機第 8、11、12 頁因內容較長而可垂直捲動，導覽列保留在底部。此行為符合小螢幕顯示需求。

此次正式版設計修正 **1 輪**，並非假裝已經進行三次修正。自動瀏覽器測試的詳細結果請看 `browser_checks.json`。

## 測試環境限制

沙盒 Chromium 對 `file://` 網址回報存取限制，因此使用 Playwright `page.set_content()` 直接載入相同 HTML 進行實際畫面測試。這不表示使用者本機或 GitHub Pages 上的 HTML 有此權限問題。網站上線後仍需檢查公開網址。
